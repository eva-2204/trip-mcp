# trip-mcp — демо travel-агента на MCP

Демонстрационный сервис travel-агента, который отвечает пользователю через **Claude**
(Anthropic API) и ищет реальные данные через настоящие **MCP-серверы**:

- **Kiwi MCP** (`https://mcp.kiwi.com`) — поиск авиабилетов, инструмент `search-flight`.
- **Trivago MCP** (`https://mcp.trivago.com/mcp`) — поиск отелей, инструменты
  `trivago-search-suggestions` → `trivago-accommodation-search`.

Все обращения к внешним данным идут **строго по протоколу MCP** (JSON-RPC поверх
Streamable HTTP, `initialize`, заголовок `Mcp-Session-Id` и т.д.) через
`@modelcontextprotocol/sdk` — никаких прямых REST-запросов к Kiwi/Trivago в обход MCP.

## Интерфейс

- Слева — чат с агентом (~40% ширины), с приветственным сообщением, индикатором
  «думает» и ответами на основе данных из MCP.
- Справа — панель логов: каждый запрос/ответ к Kiwi и Trivago (включая установку
  MCP-сессии), с компактным свёрнутым JSON (со скроллом), который можно раскрыть.

## Особенности логики агента

- **Kiwi не поддерживает российские аэропорты.** Агент (через системный промпт) и
  бэкенд (защитная проверка в `server/src/agent/tools.ts`) распознают российские
  города/аэропорты и не вызывают Kiwi для таких направлений — вместо этого
  пользователю сообщается, что Kiwi это не поддерживает.
- **Trivago не понимает русские названия городов.** Название города Claude сам
  переводит на английский перед вызовом `trivago-search-suggestions`. Дополнительно
  в `server/src/mcp/trivago.ts` есть защитный механизм: если в аргументы всё же
  попал кириллический текст, бэкенд делает отдельный короткий вызов Claude для
  перевода и логирует этот шаг («Перевод названия города через Claude»).
- Даты для Kiwi передаются в формате `dd/mm/yyyy`, как требует его MCP-инструмент.
- Схемы инструментов (`search-flight`, `trivago-*`) по возможности запрашиваются
  «вживую» у самих MCP-серверов (`tools/list`) — если сервер недоступен, используется
  запасная (fallback) схема, чтобы приложение не падало.

## Структура репозитория

```
server/   Node.js + TypeScript + Express + ws — бэкенд, MCP-клиенты, агент на Claude
client/   React + Vite + TypeScript — интерфейс (чат + панель логов)
```

## Настройка секрета ANTHROPIC_API_KEY

Приложение **не будет отвечать** без ключа Anthropic API. Создайте файл
`server/.env` на основе `server/.env.example` и впишите туда свой ключ:

```
ANTHROPIC_API_KEY=sk-ant-...
```

Если ключ не задан, сервер всё равно запускается, но в чат сразу выводится
сообщение об ошибке «Не задан ключ ANTHROPIC_API_KEY…», а любые сообщения
пользователя будут получать ту же ошибку вместо ответа.

## Запуск в режиме разработки

```bash
npm install                 # установит зависимости server и client (npm workspaces)
cp server/.env.example server/.env   # впишите свой ANTHROPIC_API_KEY

npm run dev:server          # поднимет бэкенд на http://localhost:8787
npm run dev:client          # поднимет фронтенд на http://localhost:5173 (проксирует /api и /ws)
```

Откройте `http://localhost:5173`.

## Продакшн-сборка

```bash
npm run build   # соберёт client (в client/dist) и server (в server/dist)
npm start        # поднимет express-сервер, который отдаёт собранный клиент и API/WS на одном порту
```

По умолчанию порт `8787` (переменная `PORT`).

## Сетевой доступ

Серверу нужен исходящий HTTPS-доступ к `mcp.kiwi.com` и `mcp.trivago.com`, а также к
Anthropic API. Если один из MCP-серверов недоступен (например, из-за сетевых
ограничений окружения), агент продолжает работать: он логирует ошибку подключения
в панели логов и использует запасную схему инструмента, но реальные данные,
конечно, получить не сможет, пока сеть не будет разрешена.
